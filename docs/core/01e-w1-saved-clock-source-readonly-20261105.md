## Exact scope

`inspectW1SavedClockSource(profile, context)` reads already locally decoded JSON and externally declared build metadata. It checks the saved map entry `World.RecurringEvents["155"]`, exactly one `NextOccurrence`-bearing oneof named `ItemSpawning`, its `RecurringEventItemID===2010000021`, and own fields `NextOccurrence`, `LastOccurrence`, `EndDate`. The first two must be strict Gregorian UTC `YYYY-MM-DDTHH:MM:SS[.fraction]Z`; **EndDate must be present and may be `null`** or the same UTC format. Original timestamp lexemes are returned without parsing into local time, rounding, rescheduling or normalizing; the intentional year **2126** must be left untouched. A conflicting second `NextOccurrence` variant, incorrect event identity, invalid/missing field, bad calendar or foreign BID/schema fails closed.

Matching caller SHA256/revision **format** does not authenticate original encrypted P1G, game build, decoded source, Core SID/Revision/IndexGeneration or transaction CAS. Source shape success does **not** establish when the game's startup `ActualizeRecurringEvents` uses host clock, whether an `ExecuteRecurringEvent` RPC accepts or rejects W1 due to area/Tree/Quota/quest conditions, nor whether Last→Next is updated and persisted after cold save/reopen. No comparison against wall-clock `now` is made, and `LastOccurrence > NextOccurrence` by itself is not a Native scheduler verdict. The new function intentionally returns `nativeClockActualizeVerified=false`, `nativeExecuteAcceptedVerified=false`, `nativeLastToNextVerified=false`, `nativeColdLoadVerified=false`, `nativeV3Accepted=false`; all Writer/EditedCopy/Overwrite/2126 auto-repair flags false.
