## Worker authority model
- `OPEN_LOCAL_V1` is the unchanged trusted Stage G flow. On every new Open and Close, the Worker clears the DEV read cursor state, and only the existing Rust bridge may mint/consume Core cursor tokens. No distinct JS Reader, second Rust Session, JSON parser or Editor.
- `DEV_READ_METADATA` accepts EXACTLY `{kind,requestId,domain,pageIndex}`, with `domain=player|world` and sequential `pageIndex` of 0..127. It never accepts UI SessionID, Revision, IndexGeneration, SourceSHA, ReadSet/path, cursor, entropy, JSON body or Writer permission. Rust-owned immutable receipt supplies the scope internally; the already accepted Rust adapter validates each Core-issued one-time cursor token, original SourceSHA/Revision CAS and <=16 field descriptor response.
- The Worker returns at most sixteen **metadata descriptors** per response: `{key,kind,valueBytes}`, bounded page number and Boolean `productReadAccepted:false`, `writerAuthorized:false`, `editedCopyAuthorized:false`, `applyAuthorized:false`, `physicalBuildCryptographicallyVerified:false`. It never returns field values, decoded JSON, cursor tokens, original SHA or any file object in a DEV read message.
- Worker-local per-domain sequential state prevents replay/skipping and prevents one UI thread minting its own token. A normal owner Worker rejects this command with `OWNER_LOCAL_DEV_READ_DISABLED`. On new Open or Close, old local pages are invalidated. Malformed Rust receipt/error revokes Worker state rather than granting product read authority.
- The local DEV page is a distinct `noindex` HTML/Module Worker path on the existing exact loopback GET/HEAD allowlist; HTTP POST and external origins denied by inherited CSP. No browser storage/telemetry. Existing public Pages and product Worker remain unchanged.
