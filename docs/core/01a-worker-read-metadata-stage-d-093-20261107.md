## Authority and trust
- Worker-only JS facade already obtains its initial 32-byte seed with `globalThis.crypto.getRandomValues`, rejects unavailable/all-zero entropy and strictly **rejects extra caller-supplied `entropy`/cursor/seed parameters**. The seed is used only inside the Worker and zeroed in JS after constructing the Rust WASM object; provenance cannot be verified for arbitrary caller-controlled JS realms, so this is not proof of real isolated Browser runtime. The facade is **not exported to public UI** by the production Worker.
- The **same existing Rust ProductSession** is the sole source of SessionID, Revision, IndexGeneration, decoded-source SHA, Full-Document Validation, indexed Native metadata and Close/Drop. Rust derives a **separate 256-bit private cursor key** from Worker seed + decoded SHA + domain separator; it is never returned to JS/UI. On native tests, existing getrandom CSPRNG mint behavior is preserved. On wasm32 without the opt-in worker feature/seed, `issue_indexed_cursor` fails closed. No per-call entropy or UI path crosses the WASM boundary.
- Each cursor is a 128-bit Core-generated digest of private key + source SHA + checked monotonic nonce; exactly two active grants max, 16 field descriptors per page. Token is one-use, rotates with nonce on each page, and binds to same ID, Revision, IndexGeneration, SHA. Close/Drop revokes. No raw JSON field values/100–200MiB body, dynamic path, cursor seed or untrusted DOM transport.
- `WorkerWasmSource.issue_typed_cursor(domain,sessionId,revision:u64,indexGeneration:u64,decodedSha256)` allowlists only `player|world`. `read_typed_page(cursor,...)` accepts only a Core-issued token. Rust enforces owner CAS+readset and serializes JSON **metadata descriptors** (key, kind, valueBytes) only; all authority flags remain false. The JS facade checks an **exact schema** with bounded JSON lengths, U64 `BigInt`, metadata keys <=128 UTF-8 bytes, no extra `rawValue`/nested payload, <=16 descriptors, no Writer/Apply flags, and rotates a Worker-local cursor set only after full Rust receipt validation. On forged Rust receipt it revokes the whole Worker session.
- `getCapabilities().canReadTypedMetadataInProduct=false`, `productReadAccepted=false`; `submitOperation()` always denies Stage/Apply/Export/Overwrite. Existing public JS Worker and local-save-session-bridge remain unchanged; actual Browser wasm-bindgen JS/WASM module packaging and browser execution not implemented/NOT_RUN.
