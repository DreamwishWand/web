## Transaction, all-writer enrollment and failure semantics

Provisional reads never authorize the mutation. The existing nonpublic SQL candidate acquires Artifact FOR UPDATE -> Preset Work FOR UPDATE -> associated Gallery Work FOR UPDATE -> Media FOR SHARE in deterministic Media-ID order; also uses a per-account/idempotency advisory transaction lock. After locks: verify account/Creator/owner/lifecycle/public/moderation, exact current Preset Revision, both expected Work RowVersions, exact expected Gallery current WorkRevision, linked verified Gallery subject, caller-pinned historical edge set, original paired Work identity, registered Blob metadata, and all Media READY/CLEAR/cover membership. Insert next immutable PresetRevision, Preset/Gallery WorkRevisions, GalleryCover, GalleryRevisionPreset, Media ordered membership, both current pointers, Search, Outbox and idempotency response in ONE PostgreSQL transaction. The former Gallery Revision/Cover/Media and Preset revisions are not rewritten.

**Still open:** 09 INT R11 independently proved actual two-session `pg_blocking_pids`/SQLSTATE55P03 rollback for **3/3 known reference triggers** in isolated full-schema database, but that is not 09 INT R12 accepted global contract. Global actor+reference registry spanning all current/historical lifecycle and Gallery-first/Media-first writers, five Preset types/ToM/native, moderation and account erasure is not proven. All writers must use compatible lock ordering or explicit deadlock-safe transaction design. Re-evaluate moderation and account erasure immediately before publish; emergency safety reads/takedowns must not wait on an unsafe positive retirement path.

Failure contract for eventual HTTP writer: reject missing/invalid inputs or nonowner/unsupported version without mutation; stale Gallery pointer/rowVersion/historical digest as conflict (proposed HTTP 409); foreign/purged Media or unverified Blob as authorization/validation failure; deterministic idempotency conflict on reused key/changed payload. On PostgreSQL `40P01`/`40001`/eligible `55P03` the coordinator, **not a partial SQL statement**, may retry the complete command in a fresh transaction with a strict bounded attempt budget and backoff only after actor/current/historical dependencies are reauthorized; never blindly retry a semantic conflict. The current private candidate **does not implement this coordinator**. No API error mapping or promised positive write is deployed.
