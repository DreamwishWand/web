## State machine and irreversible safety

1. **Staging / `RESERVED`:** existing Source134 Actor+Creator+idempotency-bound unique Published key and SHA. Stage JSON downloaded and checked before reservation. Same Request Hash returns original Reservation; different hash conflicts.
2. **Lease claim / `PROMOTION_IN_PROGRESS`:** new service-only `community_preset_storage_claim_promotion_r18`, Account `FOR SHARE`, Reservation `FOR UPDATE`, exact expected version, fresh server-generated lease token, monotonic `lease_fence`, 90-second expiry. Returns `providerCopyAuthorized=false`, `publicationCommitAuthorized=false`. Only `RESERVED` or explicit `FAILED_RECOVERABLE` can claim; in-flight lease cannot silently be stolen.
3. **Published Object observation:** new Owner Edge `inspectPublishedObject` independently downloads current Staging and deterministic Published keys via Storage Provider interface; validates portable Scene JSON, computes actual bytes/SHA with Web Crypto. Only when staging remains expected bytes does it report downloaded Published bytes to SQL; no `Storage.copy`, overwrite, destructive remove or external compensation. Missing Published, unavailable download or staging changed returns 409 and requires refresh/reconciliation.
4. **`VERIFICATION_REQUIRED`:** `community_preset_storage_report_readback_r18` atomically rechecks Actor, Creator, exact stateVersion, lease token, fence, lease expiration under row lock. On mismatch with Reserved size/SHA, stores `FAILED_RECOVERABLE` and leaves physical object untouched. On matching bytes, records `EDGE_READBACK_UNATTESTED` and moves to `VERIFICATION_REQUIRED`; this deliberately **does not** become `VERIFIED_PUBLISHED_OBJECT`. A caller-controlled hash, even if copied into metadata, is never accepted as independent Provider attestation.
5. **`VERIFIED_PUBLISHED_OBJECT` (inert future):** requires a separate credible Provider attestor, immutable object version/precondition, new fully reviewed privileged transition. **No production entrypoint currently sets this state.** An old process cannot Commit after lease expiry or stateVersion/fence change. Future Provider must prove no-overwrite Copy and failure/timeout/replay/version semantics before entering.
6. **Gated transactional candidate / `COMMITTED_PRESET_PUBLICATION` (inert future):** new `private.preset_storage_commit_candidate_r18` is **REVOKED to service_role, anon, authenticated and PUBLIC**; `private.preset_storage_release_gate_r18` is default OFF and private to operator. Candidate revalidates active Account/Privacy/Creator and matching reservation, unexpired lease/token/fence and explicit Provider attestation, and no existing Blob at the deterministic key. In one SQL transaction it writes Blob, new Preset Work/Artifact/Revision, immutable Work/Publication link, Search (public only), Outbox, Idempotency and committed Reservation. The published-Blob insert trigger checks a private table containing only the transaction-owned Reservation and Storage key: no public caller-supplied session variable can bypass it. Existing completed idempotent request returns the exact same response. Actual local positive-shape acceptance uses a PostgreSQL-only synthetic attestation/release override inside an explicit transaction and **ROLLBACK** afterward; never calls Provider, never makes source write routable.
7. **Crash/SQL/Copy failure Recovery:** any Copy-succeeded/SQL-failed key remains quarantined and not deleted. The next attempt must acquire a fresh Lease/Fence and re-download the destination (including Provider object version/identity), or fail closed. A client retry must not treat a 404 download as permission to blindly Copy to the deterministic key. SQL transaction failure rolls back scope, Idempotency and all Work references. Reported bytes mismatch moves to FAILED_RECOVERABLE and preserves object for inspection. Expired lease cannot commit.
8. **Cleanup / Compensation:** old Source134 `community_preset_storage_cleanup_preflight_r18` remains **DENIED unconditionally** even when DB row counts zero; `wep-preset-artifact.discard` and `wep-preset-retention` invoke no physical Storage.remove. Future scoped cleanup requires current/historical Preset/Work/Scene/Gallery and Cloud refs, all duplicate concurrent reservations, legal holds, live signed URLs/CDN, immutable object identity/version, lease and reference locks, durable claim/worker audit, orphan quota and eventual recovery. No 72h TTL authority granted.
