## P0 and contract
09 INT R15 found a stale caller intent defect. Two GalleryWorks A/B refer to the same Scene. After B preflights, A can publish a new immutable GalleryRevisionPreset edge. B's own Work rowVersion need not change. R14 rechecks the current graph *within* B's transaction but does not know the B caller's original graph and can accept its stale intent. This is not a lock bypass.

The R15 owner Source implements **two-stage server-authoritative Graph pin**:
1. The signed Owner Edge command `preflightGalleryGraph` invokes `public.community_gallery_graph_preflight_r15(authSubject, galleryWorkId, requestedPresetRevisionIds)` via the server-side admin client. R13 active/nonretired/non-suppressed identity maps the actor to an active account; all scoped Work/Artifact ownership and Creator relations are checked. No anon/authenticated SQL grant. Preflight is read-only and not a mutation authority.
2. The server returns `{schemaVersion:1, registryVersion:"gallery-scene-scoped@r15", expectedGraphSha256, expectedGraph, expectedWorkStates, expectedArtifactIds, expectedPresetWorkIds, expectedGalleryWorkIds, historicalPresetLinks, mediaReferences, coverReferences, authoritative:true, graphComplete:false}`. All digest inputs are DB-derived, not caller-supplied. Domain (registry/version), account ID, JWT subject, target, requested revisions, all known Scene Artifact/Work/current+historical rev/Media/Cover refs, rowVersions and nullable fields are bound in PostgreSQL `jsonb` canonical text, hashed with pgcrypto SHA256 of UTF8. R14 arrays are sorted by typed UUID, timestamp/object serialization uses native PostgreSQL JSONB text and must **not** be recomputed by a JavaScript implementation. SHA is 64 lowercase hex.
3. Edge command `publishGallery` requires `graphPin:{registryVersion:"gallery-scene-scoped@r15",expectedGraphSha256:"..."}`. Route is now `public.community_publish_gallery_pinned_r15`, not legacy v4. Any missing/invalid pin fails closed. R15 pinned Writer retains original Gallery v4 validation and mutation body, but verifies caller digest **after** R14 Account→Artifact→PresetWork→GalleryWork locks and current/history snapshot comparisons, **before** inserting any revision, Search, Outbox, or Idempotency.
4. Mismatch is terminal `R15_STALE_GRAPH_TERMINAL` mapped to Edge `STALE_GRAPH` / 409; it is **not retryable** and the Edge must never issue a fresh pin automatically. The prior `R14_GRAPH_CHANGED_RETRY_WHOLE_TRANSACTION` remains a whole-transaction retryable in-flight roster change. Every retry reauthorizes the JWT/session and retries with the *same caller pin*, max 3 transactions / 1.7s.
5. Legacy `public.community_publish_gallery_v4` 11-argument route retains no-Preset compatibility but rejects Scene requested or historically/directly linked with `R15_PINNED_GRAPH_REQUIRED`, preventing bypass through the previous service-role RPC. Scene publishing requires pinned R15 route.

## Idempotency / lock sequencing
R15 request hash incorporates expectedGraphSha256 and every original Gallery request field. After active identity/Privacy and Account `FOR SHARE`, **completed** same-key/same-input requests return the previously committed result without graph re-evaluation; same key with a different pin or payload is rejected. Initial committed replay lookup uses only MVCC `SELECT`, **not an early advisory lock**. Fresh writes acquire Artifact/Work locks and then original per-account/key advisory lock, preserving R14 ordering; all revisions/Search/Outbox/Idempotency commit or roll back together. A new idempotency key with an old Graph pin always reaches under-lock SHA comparison and fails stale.
