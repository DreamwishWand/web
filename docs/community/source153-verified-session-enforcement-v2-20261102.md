# Source153 verified session gate v2 — isolated server implementation and acceptance

2026-11-02 · Draft only · fixed ancestor PR288 `1755d2f37f08bb93604d1839245f8565cf603916`. This prototype is **not deployed**. Stage116, real accounts, external Provider, Managed Ingress, CDN, shared Auth client, WEB267, Owner production flags and Native Writer are untouched.

## Server trust and migration

Source153's existing withSupabase signed JWT middleware provides the verified subject, iat and GoTrue session_id; the client cannot supply identity/session fields. The new service-role-only `community_authorize_signed_session_v2` retains the existing Account and Wand Identity resolution and account-global cutoff, additionally requires an existing `auth.sessions(id, user_id)` row managed **only by GoTrue** and denies the immutable Wand `private.wand_verified_session_revocations_v1` terminal tombstone. No public self-enrollment or implicit acceptance of a missing/old Session ID. When auth.sessions is unavailable, fail closed rather than restoring legacy behavior. This dependency on GoTrue's internal PostgreSQL session table is not a publicly guaranteed cross-version contract: production migration remains blocked pending an update-compatibility and provider-owned session-lifecycle audit.

The new private tombstone is scoped to verified subject and session_id, not account for Local Logout; the service-role-only revoke RPC accepts signed claims from the Edge trusted verifier and scope local/global, never user JSON subject or session_id. Under an AuthIdentity row lock, Local stores only a terminal revocation and leaves sessions_valid_after unchanged; Global stores a tombstone and advances the existing account cutoff monotonically, blocking even older unregistered pre-cutoff JWTs, not sibling B/M. A duplicate request from the same signed Session and SAME scope is a no-op, never moving global cutoff a second time and causing accidental denial of a new A3. Scope escalation from already revoked Local A1 to Global is denied. New login A3 must be a real GoTrue-created Session after the global cutoff; second-resolution JWT iat means the acceptance test waits >1 second. Refreshing an old session_id cannot undo its terminal tombstone.

The source adds `session-revoke` as a strictly parsed Edge action, with the authenticated signer subject/session injected only server-side. The caller must invoke Wand revoke before invoking GoTrue signOut to ensure Wand server Access JWT denial; GoTrue Logout HTTP204 **alone** was already proven insufficient. On provider failure, confirmed Wand revocation still fences the Access token; on Wand DB failure, 401 with `SESSION_REVOKE_UNCONFIRMED` is NOT a successful Global/Local remote revocation and the owner UI remains OFF. In-flight private read responses receive a second server gate just before projection release; no claim of DB-atomic Write mutation revalidation is made and all Owner Writer/Publish/Grant/Delete features remain OFF.
