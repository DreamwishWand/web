## Scope and authoritative DB projection

Additive SQL: `supabase/migrations/20261025003030_r19_preset_postcommit_read_suppression.sql`. Existing Source137 Reporter and Source138 Commit all-fence veto remain the transaction authority. Once a **committed** Preset Blob has an unresolved Source137 `QUARANTINED_PENDING_OPERATOR` incident on its Reservation, new `private.preset_storage_work_quarantined_r19(work_id)` resolves the affected Preset Work and **all historical GalleryWorkRevisions** linking its PresetRevision (not merely current published GalleryRevision). It queries the immutable incident and sealed revision graph; it cannot infer DDV-specific Scene/Cloud/ToM or off-system references.

`AFTER INSERT` on the Incident journal records `private.preset_storage_work_read_suppressions_r19` for the affected Preset and historically linked Gallery Works and deletes their `public.search_documents` rows in the **same database transaction** as the Incident record. A Search BEFORE INSERT/UPDATE guard blocks denormalized rediscovery. A restrictive RLS SELECT policy denies quarantined CommunityWork, SearchDocument, PresetArtifact, GalleryRevisionPreset, WorkRevisionMedia and MediaAsset reads to ordinary `anon`/`authenticated` callers. **Service-role and SECURITY DEFINER bypass RLS**, so RLS alone is not authority: existing `wep_get_accessible_preset_blob`, `community_get_preset`, `community_get_gallery_public_v1`, `community_get_gallery_v1` are redefined preserving existing privacy/moderation checks and enforcing explicit quarantine veto. This blocks *new* `wep-preset-artifact.read` signed URL issuance because the Edge calls `wep_get_accessible_preset_blob` before `createSignedUrl`.

New `private.preset_storage_media_quarantined_r19(media_id)` checks all historical WorkRevisionMedia links to affected Gallery Works. `public.community_preset_storage_assert_media_not_quarantined_r19(media_id)` is a service-role-only negative gate. Both Source Edge `community-public-media` (public Gateway, GET streaming + legacy POST signed URL fallback) and `community-media` (Owner signed/proxy fallback) call it before their old Gateway/Storage operations. If the RPC is absent or errors during partial rollout, they fail closed with 503 rather than fall back to signed URL. Existing DreamSnaps unrelated to an incident do not become globally forbidden. A reusable image linked to a quarantined Gallery is suppressed on every route invoking the new helper; this is intentional safety-first.

### Important limits

- **Current/known historical graph coverage:** direct PresetRevision → ArtifactBlob → Reservation; GalleryRevisionPreset across ALL historical GalleryWorkRevisions; Gallery media attached to affected WorkRevisionMedia; direct Owner/public Preset and Gallery detail RPCs, Source Edges for WEP Preset download and Gallery media. Separate Scene paired-photo / Cloud linked-copy / independent Gallery issuers, alternate SQL projections and external consumers are NOT proven closed. These must remain disabled or undergo an independent issuer inventory before launch. A direct service-role query outside these guarded entrypoints still bypasses RLS.
- **Bearer/CDN:** a Storage signed URL issued BEFORE the incident, a browser/CDN cached response, already streaming bytes or third-party copies cannot be recalled merely by SQL Search deletion or an Edge preflight. Old bearer t0/t60/t300s/expiry, CDN warm/cold, cache purge and legal/privacy erasure require Operator-authorized real Provider acceptance. `Cache-Control: private, no-store` reduces caching but is NOT retroactive revocation.
- **Transaction race:** Source137 Reporter holds Account SHARE → Reservation UPDATE and inserts incident + projection in one SQL transaction. Source138 Commit takes identical locks; reporter-first prevents Commit and suppresses future reads. Commit-first can complete, then reporter quarantines the now-committed Work/Blob/Gallery; *new* statements after incident commit deny. Reads that completed before incident commit are not retroactively revoked. The read guard is DB snapshot semantics, not a distributed cross-provider transaction.

## Version-fenced Operator Resolution — no public positive path

`public.community_preset_storage_resolution_readiness_r19` validates signed-Edge-supplied Actor → active Account and independent Phase1 Privacy Suppression under Account SHARE → Reservation UPDATE; Owner/Creator, moderation=clear and exact StateVersion+LeaseFence. The only possible response has `versionFencedResolutionAuthorized=false`, `operatorApprovalRequired=true`, `independentProviderVersionAndBytesRequired=true`, and count of **ALL old/current Fence incidents**. No `UPDATE` or `DELETE` of Source137 immutable Incident is allowed. A future reviewed Operator-only authority would require a separate append-only evidence record with independent signed provider issuer identity, immutable Object Generation/ETag, actual downloaded SHA256 and size, source generation, keyed Reservation/Fence/RequestHash, idempotent audit trail, legal/Privacy/Moderator recheck, complete graph lock and signed session audit **before** any resolution CAS. Do not convert `EDGE_READBACK_UNATTESTED` or local `O_EXCL` evidence into `PROVIDER_ATTESTED`.

A postcommit missing provider object currently has no tested safe automatic repair: keep suppressed; reconciliation must distinguish transient Provider 404, remote stale cache, generation mismatch and byte corruption; never overwrite a published key, replay a previous response, or compensate with Physical Remove.

## Reference-aware cleanup preflight — no Claim/Remove

`public.community_preset_storage_cleanup_inventory_r19` validates Owner, Account/Privacy, locks the Reservation and reports historical PresetRevision/GalleryRevisionPreset references + incident count. **It is not a Cleanup Claim** and always reports `cleanupClaimAuthorized=false`, `physicalDeleteAuthorized=false`, `cloudAndLinkedProfileReferenceGraphProven=false`, `legalHoldAndModeratorClearanceProven=false`, `previouslyIssuedBearerAndCdnRevocationProven=false`. Unknown Scene, Preset, Gallery, Cloud, media, signed bearer or legal reference => deny. A future Claim requires atomic transaction with Owner/Creator/Cloud/Moderator/legal holds, all current/historical references and concurrent Reservations/Lease, exact Object Version fence and worker recheck before provider-conditional Delete; must never delete a Winner or return Cleanup success on provider 404.

## Provider-origin verification

Current Supabase official docs for `storage.from(bucket).copy(src,dst)`: Copy requires read-source/insert-destination and can upsert with UPDATE privilege; docs do **NOT** specify a single required atomic destination If-None-Match + immutable source generation precondition + authoritative version-bound Published Read + independent Provider-signed byte evidence. The documented normal upload `upsert=false` is not proof for COPY source-version fencing. Until verified using an Operator-approved **genuine** Supabase provider and normal signed OwnerA/B/ModeratorM with protected disposable objects and independently checked provider identities, these capabilities remain **UNKNOWN / NOT_EXECUTED**. Source137/local O_EXCL only supports logical contract, not remote guarantee. No live Storage mutation or SQL deploy was performed.
