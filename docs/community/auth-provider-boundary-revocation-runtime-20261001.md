## Password provider boundary — CONFIRMED RUNTIME

A temporary staging-only acceptance function exercised Supabase Auth directly using disposable
confirmed users created by the provider Admin API.

Observed acceptance contract:

- 14-character ASCII password: **rejected**;
- 15-character ASCII password: **accepted**;
- no character-composition requirement was introduced;
- the accepted 15-character account could sign in normally.

The acceptance function returns HTTP 500 if either boundary assertion fails. The live invocation
completed HTTP 200 on function version 6.

This closes the previously pending provider-side minimum-length boundary. The browser-side
15-code-point validation remains aligned with the provider minimum.

No signup confirmation email was generated by this test because the disposable account used the
provider Admin create-user path with email already confirmed.

## Provider + Wand revocation — CONFIRMED RUNTIME

The same disposable 15-character account created two real Supabase password sessions.

The runtime sequence was:

1. both sessions authenticated successfully;
2. WandAccount + CreatorProfile bootstrap succeeded;
3. the second session successfully reached the normal Community query boundary;
4. provider global logout was executed from the first session;
5. Wand `revokeSessions` advanced the independent Wand session cutoff;
6. the second session's old JWT was rejected by Community with
   `401 SESSION_REVOKED_OR_INVALID`;
7. the second session's provider refresh token was rejected after global logout;
8. a new password sign-in after the cutoff succeeded;
9. the fresh session performed normal self-service account deletion.

Independent database evidence after the run:

- one new `auth.sessions_revoked` AuditEvent;
- one deleted disposable WandAccount;
- no open provider-cleanup job;
- disposable provider users remaining: 0;
- disposable CreatorProfile handles remaining: 0.

The deletion contract intentionally leaves one AccountDeletionEvent plus two future retention jobs
(content + operational). Those are normal retention/audit state and were not bypass-deleted.
