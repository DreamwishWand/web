## 3. R15 multi-writer atomic transaction candidate

`ddv.atomic.allwriters@r15` input:
- `actor.subject` from actually verified JWT, session id/iat, real `auth_identities.identity_state='active' AND retired_at IS NULL`, active Account and Creator ownership, moderator staff exceptions; all affected Account IDs and privacy suppression epoch.
- `operation`, idempotency key/digest, Source contract/build, `expectedRegistryVersion`, `expectedGraphSha256` (distinct from `scene-historical-edges-v1`), graph-root Artifact and Work IDs, old/new associations, current+**all historical** revision/Media/Cover edges, Media binary checksum+bytes owner READY/CLEAR receipt, native and Cloud/retention flags.
- Expected Artifact/Owner/Creator/facet; every PresetWork/GalleryWork current Revision, RowVersion, lifecycle, visibility and moderation.

Algorithm (must be owned by 03 COMM, NOT test harness):
1. Verify signed/current subject and account privacy before any mutable work. Acquire Account roots in sorted UUID order (`FOR SHARE` for regular write, `FOR UPDATE` for privacy) **before any Artifact/Work lock**. Consider current account idempotency advisory and reference-trigger lock order; unproven orders may cause 40P01.
2. Discover all old+new edges, cross-linked Artifacts and Work versions, foreign account owners, Registry. Unknown facet/reference type = FAIL CLOSED. Never substitute current Work `row_version` for immutable historical edge enumeration.
3. Acquire **sorted Artifact IDs**, **sorted PresetWork IDs**, **sorted GalleryWork IDs**. Re-enumerate graph while held. If a new lock target appeared or any owner/creator/Work/current pointer/digest changed, ABORT entire transaction; do not acquire a late, out-of-order extra lock. Report stale caller as terminal unless refreshed by *new user preflight*, not silent replay.
4. Atomic immutable revisions, Gallery/Scene association, Search+Outbox+Idempotency+Audit in one database transaction. Storage signed-URL issue only after authorized commit and active privacy re-check.
5. Retry only transient **40P01 / 55P03 / 40001** at whole-request level, maximum 3 attempts including first, new DB transaction and fresh signed actor/account status/graph/checksum/Work versions; jitter/deadline/backpressure. Errors for retired actor, unknown registry, changed caller fingerprint, real rowVersion/permission mismatches are **terminal** and NOT automatically refreshed to authorize a new semantic result.
6. Account privacy phase1 and moderator **restrict/remove** must remain prompt and independently readable across deferred Gallery/Cloud/Media cleanup; positive *restore* requires full all-writer proof.

**Contract hazard**: if two Gallery-first Writers touch different Gallery Work but a common historical Preset Artifact or cross-link, just ordering Gallery rows independently is not sufficient. A newly minted historical GalleryRevisionPreset edge changes graph without changing the original PresetWork rowVersion or linked old GalleryWork rowVersion; caller fingerprint and dependency registry coverage are mandatory. Source v4 supports max **one** PresetRevision per call; testing two in one call violates actual API. R15 tests two real Source publish calls against shared Account/graph instead.
