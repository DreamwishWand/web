## B. Deterministic atomic writer contract (owner implementation requirement)

Transaction key `ddv.allwriter@r14`: Caller carries real verified signed subject+recent session where needed, `idempotencyKey`, expected root `AccountIdentity+privacy epoch`, `PresetArtifactId+owner+creator+kind`, expected target `PresetWorkId/current WorkRevision/rowVersion`, **all** reachable `GalleryWorkId/current WorkRevision/rowVersion` records, expected `all-kind current/history graph SHA256` with versioned registry signature, and immutable blob sha/size + media/cover receipt where relevant. All unknown graph types must FAIL CLOSED. R9 scoped historical Scene SHA remains a separate required component, never a substitute.

Transaction sequence:
1. Verify real signed actor; current AuthIdentity MUST be `active` and owned by active, non-suppressed account; check moderator/staff role separately. `private.resolve_active_account` in inspected PR134 46042485 Source still lacks `i.identity_state='active'` predicate, owner fix #134 mandatory. First lock every affected Account root UUID sorted (`FOR SHARE` for positive owner writers, `FOR UPDATE` for suppression) **BEFORE any Artifact or Work row**. Ensure idempotency advisory acquisition order cannot invert Account/Artifact locks in another writer.
2. Provisional versioned ALL-kind graph reverse-discovery including old & new edge namespaces: `preset_artifacts` (direct associated gallery), `preset_revisions`, all `preset_revision_publications`, all gallery current and historical `gallery_revision_presets`, all Gallery WorkRevisions/current pointers, historical `work_revision_media`, Cover, Cloud private/URL issuer references, subject/native roster and moderation/privacy. Include cross-linked artifacts and every owner. If graph registry UNKNOWN, no mutation.
3. Sorted Artifact UUIDs `FOR UPDATE` then sorted PresetWork IDs `FOR UPDATE`, then sorted GalleryWork UUIDs `FOR UPDATE`. Any post-lock graph discovery of previously unknown node, edge/owner/version mismatch or newly reachable lock target => rollback **whole transaction** and start over from Account root with freshly resolved graph. Do not lock newly discovered out-of-order row. All locks must be authorized against actor/Owner/Creator, current and historical.
4. Re-read actor/active AuthIdentity, suppression, Creator ownership, target Work rowVersion+current Revision, all immutable ancestry and full graph checksum *under all locks*; terminal stale caller hash mismatch requires new user preflight (do not auto overwrite fresh expected values). Recheck Media checksum/size/READY/CLEAR/owning account and actual bytes/Storage receipt before any positive public API.
5. Within same DB transaction, write immutable Preset/Gallery Revision/links, current pointers, Search/Outbox/idempotency exactly once. On error rollback all metadata/projections/jobs; do not prematurely issue public signed Media URI.
6. Retry `40P01`/`55P03`/`40001` at most three attempts total with bounded deadline & jitter, **new database transaction** and new actor/owner/Creator/graph/privacy authorization every time. Never retry statement/savepoint or reuse stale authorization. Nontransient privacy/permission/actor/version/hash/media failures terminal; inject metrics. R14 isolated driver demonstrates a manual fresh whole transaction after `55P03`, not an approved deployed automatic retry.
7. Moderator emergency restrict/remove and Account Privacy Phase 1 suppress public reads/media right away, independent of optional cloud/physical deferred lifecycle. Positive restoration and full deletion are not authorized by this exception.
