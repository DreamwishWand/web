## Candidate DB transaction protocol for review

1. Resolve Actor / Moderator right / recent-auth account erasure, request hash and idempotency key. Restrict lock amplification: reject obvious nonowner IDs **before locking**. Actual permission must be **rechecked while Work rows are locked**. Caller-side impersonation is unacceptable.
2. Before *any* Work row lock, discover candidate dependencies from authoritative `preset_artifacts.community_work_id`, old/new `associated_gallery_work_id`, `gallery_revision_presets`, `preset_revision_publications`, current+historical sealed revisions and any supported registry. Missing/out-of-scope relation → fail closed for Gallery retirement.
3. Acquire PresetArtifact rows in UUID order, then PresetWork UUID order, then GalleryWork UUID order, one explicit ordered `SELECT FOR UPDATE` per row. No unsorted paired `UPDATE ... IN (...)` until locks are held. Every writer must participate; **Gallery-first publisher can deadlock** with Artifact-first paths if modified late. Moderation/erasure account/case locks need a verified global hierarchy against ordinary writers and FK locks before deployment.
4. While all locks held, rediscover IDs, current+historical public references, owner/creator and attached DDV subject version, revisions, publication/visibility/moderation, media cover binding. Compare **graphFingerprint + expected RowVersion/current Revision** with version-pinned caller preflight. New dependent edges may leave Gallery rowVersion unchanged. Reject stale pins or missing registry rather than silently reauthorize.
5. Mutation Work/Revision/Reference, Search, Outbox and Idempotency response in a single DB transaction. Media object writes and signed URL/CDN revocation are **separate physical acceptance gates**, not covered by DB rollback.
6. DB `40P01`, `55P03`, `40001` → rollback complete transaction, bounded **server-owned whole-command retry**, start new DB transaction, resolve actor+right+graph again. Proposed cap 3 with jitter/backoff, pending 03 COMM operational acceptance; fatal owner change / stale graph pin / publication rights errors are terminal semantic conflicts. Never reuse aborted transaction or reuse the old authorization snapshot. The R7 fixture **does not** demonstrate a deployed automatic retry coordinator.
7. Account Erasure and Moderation require legally/safety necessary immediate hidden read policy even if the Gallery graph is incomplete, then atomic canonical Work/Projection reconciliation and safe deferred media cleanup. Do not treat `retirementAuthorized=false` as authority to ignore account deletion or active abuse moderation.
