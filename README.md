# Dreamwish Wand / Web — starter v0.1

The first public-facing **UI preview** for Dreamwish Wand. Original visual direction: a magical blue night sky in dark mode and a more playful, pastel blue morning in light mode. No Disney/game art, official item DB, or user save is bundled. This repo is an unofficial fan project, not affiliated with Disney or Gameloft.

## What works

- Responsive home with four distinct cards, global header/footer, and dark/light toggle; the theme preference alone is saved in the browser's `localStorage`.
- Prerendered routes: `/`, `/explore/`, `/editor/`, `/editor/items/`, `/editor/world/`, `/help/`, `/projects/`.
- `/editor/items/` contains a **presentation-only demo** of colorful icons with working category/search filtering. It contains no genuine game data or save editing.
- GitHub Actions checks, builds and deploys static content to the GitHub Pages project URL.

**Not implemented:** profile import, encryption/decryption, actual item thumbnails and data, save edits, backup/export, bug-report submissions, cloud storage, World Editor. No production or private save is in this repository.

## Requirements

Node.js 22 (22.12+), npm, Git. If you already have a local checkout, copy only the starter files you want into it and review the diff first. Do **not** copy a `.git` folder from anywhere else.

## Run locally

```sh
npm install
npm run check
npm test
npm run dev
```

Open the URL displayed by Vite (usually `http://localhost:5173/`). `npm install` produces `package-lock.json`; **include that file in your next manual commit** for reproducible CI. The initial workflow falls back to `npm install` only when the lockfile has not yet been uploaded. `node_modules`, `build`, `.svelte-kit` and `.env*` must not be committed. Never place decrypted/encrypted saves, game dumps, keys or receipts in a public or Pages-deployed repo.

Test the same base path as GitHub Pages, if necessary:

```sh
# Bash:
BASE_PATH=/web npm run build
# Windows PowerShell:
$env:BASE_PATH='/web'; npm run build; Remove-Item Env:BASE_PATH
```

## Manual publish to the existing repository

1. Clone `https://github.com/DreamwishWand/web` as yourself, or open your existing checkout.
2. Copy the *contents* of this ZIP's `dreamwishwand-web-starter` folder into the repository root. Include hidden `.github`, `.gitignore` and `.nojekyll` files; do not upload the ZIP itself as the website.
3. Run `npm install`, `npm run check`, `npm test`, and `npm run build` locally. Include `package-lock.json` generated by npm. The initial ZIP cannot include a lockfile because the build environment cannot reach npm; verify locally before the first publication.
4. Review `git status` and the diff; commit and push from your GitHub identity. ChatGPT does not commit or deploy anything directly.
5. In the repository, open **Settings → Pages → Build and deployment → Source → GitHub Actions**. If Pages is unavailable because the repository is private on GitHub Free for organizations, choose a plan/repository visibility that supports it **before** enabling Pages. The published Pages site is typically public even when the source repository is private.
6. Go to **Actions** and confirm the Pages workflow succeeds, then use the Pages **Visit site** link. The expected initial project URL is `https://dreamwishwand.github.io/web/` (unless GitHub assigns a different domain).

For a GitHub web upload rather than Git, you must still generate `package-lock.json` locally and upload `.github/workflows/pages.yml` preserving that exact path. Web upload support for hidden files/directories varies; Git CLI is more dependable for this multi-file project.

## Custom domain later

`BASE_PATH: /web` is for the default **project** Pages URL. When switching the Pages site to a root custom domain such as `dreamwishwand.com`, change the workflow's `BASE_PATH` to an empty string, configure the domain in **Settings → Pages**, and set DNS according to GitHub's instructions. Avoid assuming a domain is configured merely because you own it.

## Data and security

The demo stores only the selected theme in localStorage. No save files are requested. Later, all save import/edit/export must be local-first with validated game version, explicit operation allowlist, backup completion and independent re-import/validation. Keep raw evidence and experimental adapters in the private DDVRE research storage; only reviewed, distributable assets belong in this web repo.

For GitHub Pages details: https://svelte.dev/docs/kit/adapter-static and https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages
